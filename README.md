# 密码实验室 · Color Code Lab

一个无第三方运行依赖的中文网页版逻辑游戏：从 7 种颜色中选出 4 种不同颜色，在 7 次内猜出密码与排列顺序。包含实时决策搜索树，方便观察每次反馈如何缩小候选范围。

## 功能

- **初级模式**：每盏提示灯对应同一位置的猜测颜色。
- **高级模式**：只显示完全命中、颜色命中但位置错误的数量。
- 鼠标、触屏与键盘操作，支持重新开局、胜负提示与答案揭晓。
- 根据全部历史反馈实时过滤候选，并高亮实际走过的决策路径。
- 点开其他反馈分支，分页查看候选答案，继续展开模拟试探或返回上一层。
- 提交前预览自己的猜测，或填入计算出的建议组合。
- 支持 Web Worker；不支持 Worker 时使用异步计算回退。
- 在支持 `document.modelContext` 的浏览器中，提供读取对局、提交猜测、开始新局三个 WebMCP 操作。

## 本地运行

需要 Node.js 20 或以上版本，不需要执行 `npm install`。

```bash
npm start
```

浏览器打开 <http://127.0.0.1:5173>。停止服务器使用 `Ctrl+C`。

也可以在项目根目录使用 Python 静态服务器：

```bash
python3 -m http.server 5173 --directory public
```

请通过 HTTP 访问页面；直接双击 HTML 文件可能受到浏览器的 Worker 限制。

## 检查与验证

```bash
npm run check
npm test
npm run verify-strategy
```

- `check`：检查 JavaScript 语法、HTML 的本地引用，以及 Worker 的依赖文件。
- `test`：计分、候选过滤、推荐组合、键盘提交、胜负、模式切换、树更新、分支探索与 Worker 消息检查。
- `verify-strategy`：遍历 840 个密码对应的建议策略决策树，统计完整提交所需的次数。

测试中的界面检查使用轻量 DOM 模型和独立 Worker VM，不等同于真实浏览器视觉、布局或 WebMCP 兼容性验收。

## 操作

颜色编号：`1 红 / 2 橙 / 3 黄 / 4 绿 / 5 蓝 / 6 紫 / 7 青`。

- 点击颜色填入当前格；点击格子选择修改位置。
- 选择已在组合中的颜色时，会交换相关格子，保持颜色不重复。
- `1–7` 选色，左右方向键切换格子，`Backspace / Delete` 清除当前格。
- 从颜色、格子或提交按钮按 `Enter` 可提交完整猜测。
- 分支探索不会消耗实际游戏的猜测次数。

## 决策策略

总密码数为 `7 × 6 × 5 × 4 = 840`。每次收到提示，保留与全部历史提示一致的候选。

建议算法遍历全部 840 个合法猜测，选择使“最不利反馈下剩余候选数”最少的猜测。并列时优先选择仍可能是答案的组合，再按颜色编号的字典序选择。

从初始状态开始、每轮均采用本项目建议时，遍历结果如下：

| 模式 | 1 次 | 2 次 | 3 次 | 4 次 | 5 次 | 6 次 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 初级 | 1 | 43 | 569 | 227 | 0 | 0 |
| 高级 | 1 | 2 | 59 | 378 | 379 | 21 |

两行都覆盖全部 840 个密码。次数包含最终提交正确组合。这个统计验证该具体策略的上限，不是对所有规则变体的结论，也不能单独证明少一次的策略必然不存在。玩家自行选择其他猜测时，剩余步数不受这份统计保证。

决策树只接收模式、已提交猜测和公开反馈，不接收隐藏密码。答案在游戏状态中保存在客户端，所以本项目是本地逻辑练习，不提供防作弊机制。

## 部署与修改

将 `public/` 中的全部文件作为静态网站发布即可。HTML、CSS、JavaScript 和 Worker 使用相对路径，可部署在站点根目录或子目录。无需后端、数据库、账号、API 密钥或构建步骤。

改界面主要编辑 `index.html`、`style.css`、`tree.css`；改推荐策略编辑 `decision.js`。若改变颜色数、密码长度或重复规则，需要同时修改游戏、反馈编码、枚举与测试。

源码包中不包含原托管站点的身份配置、凭据、临时分析文件或 Git 历史。刷新页面会开始新局，对局不持久保存。
