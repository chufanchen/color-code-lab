# 候选过滤与决策树

## 反馈编码

内部颜色编号为 `0–6`，界面编号为 `1–7`。密码和猜测均为四个互不相同的整数。

高级模式的反馈为 `(exact, misplaced)`：

- `exact`：同颜色、同位置的数量。
- `misplaced`：颜色存在于密码中，但位置错误的数量。
- 编码为 `exact * 5 + misplaced`，全对编码为 `20`。

初级模式将每一格编码为 `0 灰 / 1 白 / 2 绿`。四格按三进制权重 `1, 3, 9, 27` 相加。全对编码为 `80`，每格提示的位置被保留。

## 历史路径

初始候选集合包含全部 840 个密码。对于一条已提交猜测：

1. 对当前每个候选计算它会返回的反馈。
2. 按反馈编码分组；每组就是一个可能的后续分支。
3. 将真实反馈对应的组作为下一轮候选集合。
4. 记录其余组，供界面探索。

`trace(history, mode)` 重放上述过程。由于每一轮都在上一轮的候选集合中继续过滤，最终候选同时符合全部历史反馈。

初级和高级必须采用各自的反馈编码过滤；高级过滤不会使用本来没有公开的逐格提示。

## 推荐下一次猜测

对每一个合法猜测 `g`，将当前候选按其反馈分组，定义：

```text
worst(g) = 最大反馈组的候选数
```

选择 `worst(g)` 最小的猜测。并列时：

1. 优先选当前候选中的组合。
2. 再按颜色编号字典序选择。

这是一种单步 minimax 启发式，而不是搜索全部后续轮次的全局最优算法。允许试探已经不可能是答案的合法组合，因为这样的猜测仍可能有效区分其他候选。

后台计算预先缓存 `840 × 840` 的反馈矩阵，使用 `Uint8Array`。每种模式的矩阵约为 689 KiB。单次推荐最多检查 `840 × 候选数` 个反馈；如果某个猜测的最大分组已超过当前最优值，就提前停止检查这个猜测。

## 模拟分支与实际对局

界面把实际已提交的猜测作为主路径，并按真实反馈高亮分支。未走分支可以查看候选、继续试探，并返回上一层；这些操作不提交游戏猜测。

`tree.js` 的入口只接收公开快照和“填入草稿”回调。快照包含模式、历史反馈、草稿和对局状态，不包含隐藏密码。

异步计算使用版本号防止旧局的结果覆盖新局。每次提交或重新开局都会重新计算实际路径，并关闭旧的模拟探索。

## 验证范围

`verify-strategy.cjs` 从全部候选开始，遍历推荐猜测产生的每一个非空反馈分支。命中全对反馈时记录完整提交次数，其他分支递归继续。

初级最大次数为 4，高级最大次数为 6；每种模式恰好覆盖 840 个密码。这是当前建议算法在初始规则下的遍历结果。该验证脚本不搜索所有可能策略，因此不提供“5 次高级策略不可能”的最优性证明。
